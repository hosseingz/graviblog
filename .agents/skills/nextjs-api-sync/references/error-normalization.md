# Django REST Framework Error Normalization

This reference documents the error taxonomy emitted by Django REST Framework (DRF) and describes the prioritized parsing pipeline implemented in `errorUtils.ts` to normalize disparate payloads into user-friendly error messages and structured form validation maps.

---

## 1. DRF Error Taxonomy & Payload Variations

Django REST Framework responses vary depending on the originating layer (serializer validation, view exceptions, permission checks, or reverse proxy failures):

### 1.1 Field Validation Arrays
Generated by `serializers.ValidationError`:
```json
{
  "username": [
    "A user with that username already exists."
  ],
  "password": [
    "This password is too short. It must contain at least 8 characters.",
    "This password is too common."
  ]
}
```

### 1.2 Non-Field Validation Errors
Generated when cross-field validation fails in `Serializer.validate()`:
```json
{
  "non_field_errors": [
    "Unable to log in with provided credentials."
  ]
}
```

### 1.3 Built-in Exception Details
Emitted by DRF's standard exception handler for authentication, permission, and not-found states:
```json
{
  "detail": "Authentication credentials were not provided."
}
```
Or with custom throttling metadata:
```json
{
  "detail": "Request was throttled. Expected available in 58 seconds."
}
```

### 1.4 Custom API Error Wrappers
Commonly returned by third-party packages (e.g., SimpleJWT, dj-rest-auth) or custom views:
```json
{
  "error": "Token is invalid or expired",
  "code": "token_not_valid"
}
```
Or:
```json
{
  "message": "The verification code is incorrect or has expired."
}
```

### 1.5 Deeply Nested Field Dictionaries
Generated when validating nested serializers (e.g., User -> Profile):
```json
{
  "profile": {
    "phone_number": [
      "Phone number must be entered in the format: '+999999999'."
    ],
    "address": {
      "postal_code": [
        "Enter a valid postal code."
      ]
    }
  }
}
```

### 1.6 Transport & Gateway Failures
Generated by Nginx, Docker network timeouts, or unhandled 500 Django debug crashes:
```html
<!DOCTYPE html>
<html>
<head><title>502 Bad Gateway</title></head>
<body><h1>502 Bad Gateway</h1></body>
</html>
```

## 2. Prioritized Normalization Pipeline

To convert these disparate structures into a clean, actionable message for toast notifications, banners, or form alerts, `extractErrorMessage` executes an 8-stage priority pipeline:

```
[ Caught Error Object ]
          │
          ▼
1. Is it a raw string? ─────────────────────────► Return string directly
          │ No
          ▼
2. Extract payload (`response.data` or `data`)
          │
          ▼
3. Is payload HTML/Text? ────────────────────────► Return clean HTTP / Server status
          │ No
          ▼
4. Is payload an Array? ─────────────────────────► Extract first element recursively
          │ No
          ▼
5. Check `detail` field ─────────────────────────► Return detail string
          │ Not found
          ▼
6. Check `non_field_errors` field ───────────────► Return primary non-field error
          │ Not found
          ▼
7. Check `error` or `message` keys ──────────────► Return error/message string
          │ Not found
          ▼
8. Scan domain fields (e.g. `username: ...`) ────► Format as "field: error message"
          │ Not found
          ▼
9. Check transport errors (`ECONNABORTED`, etc.) ─► Return network status message
          │ Not found
          ▼
10. Final Fallback ──────────────────────────────► "An unexpected error occurred. Please try again."
```

## 3. Integration Patterns

### 3.1 Global Toast Notifications
```typescript
import { extractErrorMessage } from './resources/errorUtils';
import { apiClient } from './resources/apiClient';

try {
  await apiClient.post('/api/v2/auth/login/', credentials);
} catch (err) {
  const message = extractErrorMessage(err);
  toast.error(message);
}
```

### 3.2 Form Library Integration (React Hook Form)
```typescript
import { extractFieldErrors, extractErrorMessage } from './resources/errorUtils';

try {
  await apiClient.post('/api/v2/auth/register/', formData);
} catch (err) {
  const fieldErrors = extractFieldErrors(err);

  // Bind individual field errors to form inputs
  Object.entries(fieldErrors).forEach(([field, errors]) => {
    setError(field as any, { type: 'server', message: errors[0] });
  });

  // Display general alert if no specific field error was mapped
  if (Object.keys(fieldErrors).length === 0) {
    setGeneralError(extractErrorMessage(err));
  }
}
```
